# Contributing to MDOCSS

MDOCSS is intended to remain simple, open, and independently implementable.

Before proposing a change to the core specification, consider whether the requirement belongs in the container format or can be implemented as an optional convention.

## Principles

1. Preserve plain Markdown as the canonical recoverable content.
2. Prefer existing open standards over MDOCSS-specific inventions.
3. Keep required archive structure minimal.
4. Design for graceful degradation and forward compatibility.
5. Treat document contents as untrusted input.
6. Avoid requirements that tie the format to one application or vendor.

For specification changes, open an issue describing the interoperability problem before changing normative behavior.
